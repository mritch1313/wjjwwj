========================================
ГРАФИЧЕСКАЯ АРХИТЕКТУРА GODOT

Используй тот renderer Godot, который фактически совместим с целевым Android-устройством и проверенной средой.

Предпочитай Godot Mobile renderer, если он совместим с реальным target pipeline и доступными GPU/API.

Если для реального целевого устройства требуется более совместимый вариант:

используй Compatibility renderer.

Не выбирай renderer только по названию.

Проверь фактическую совместимость среды и объясни выбор.

Не использовать без необходимости:

тяжёлый realtime GI

тяжёлые volumetric effects

дорогие realtime reflections

SSR

огромные shadow maps

экстремальные particle effects

Эффекты должны быть подчинены мобильной производительности.

МИР ДОЛЖЕН БЫТЬ БОЛЬШИМ, НО НЕ ПУСТЫМ

Очень важно:

НЕ добивайся размера мира просто увеличением пустой земли.

Каждая крупная зона должна иметь визуальную структуру.

Например:

поля -> природные объекты + заборы + рельеф

пустыня -> дальние формы рельефа + камни + дороги + редкие объекты

Это создаёт ощущение большой карты без чрезмерных затрат памяти.

Когда chunk далеко:

отключай ненужную физику

отключай дорогие скрипты

отключай подробные коллизии

уменьшай частоту обновлений

При необходимости полностью выгружай второстепенные объекты.

Когда chunk приближается:

подгружай более детальную геометрию

коллизии

декорации

AI data

navigation data

Не держи весь мир одновременно в полном качестве.
